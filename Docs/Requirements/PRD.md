## Purpose

Define product behavior and testable acceptance criteria for VidOrient. Requirements are implementation-neutral; stack and API shapes live in the TDD.

## Requirements

| ID | Requirement | Traces | Acceptance |
| --- | --- | --- | --- |
| PRD-001 | The product shall let the operator navigate local directories and list video files in the current directory. | URD-001 | Given a readable folder path, the operator can move to parent/home/subfolders and see directories and video files for that path only. |
| PRD-002 | The product shall scan a chosen folder for video files with extensions `.mp4`, `.mov`, and `.m4v`, optionally recursively. | URD-002 | Given a folder and recursive on/off, the scan returns only those extensions and respects the recursion setting. |
| PRD-003 | The product shall omit directories named `archive` and hidden directories from browse and scan. | URD-009 | Files under an `archive` directory do not appear in browse listings or scan results. |
| PRD-004 | The product shall analyze each scanned video for rotation and size enough to recommend action. | URD-003 | Each successful scan item exposes rotation and suggestion flags for rotation fix, large-MOV optimization, and MOV conversion as defined in PRD-005. |
| PRD-005 | The product shall recommend: rotation fix when rotation is non-zero; optimization when the file is `.mov` and larger than 100MB; conversion when the file is `.mov`. | URD-003 | Suggestions match those rules for every successfully probed file. |
| PRD-006 | After a scan, the product should auto-select files that need rotation fix or large-MOV optimization. | URD-004 | Convert-only MOVs under 100MB with no rotation need are not auto-selected; rotation or large-MOV items are. |
| PRD-007 | The operator shall be able to select or deselect individual scanned files and process the selected set. | URD-004 | Selecting multiple files and starting processing enqueues work for each selected file. |
| PRD-008 | Processing shall produce an MP4 output beside the source: `.mov` → `{basename}.mp4`; `.mp4`/`.m4v` → `{basename}.fixed.mp4`. | URD-005, URD-006 | Output path naming matches those rules after a successful job. |
| PRD-009 | When rotation fix is requested and rotation is non-zero, the output shall bake orientation into the video so players that ignore rotate tags display correctly. | URD-005 | A file with non-zero rotation processed with fixRotation yields upright playback without relying on rotate metadata. |
| PRD-010 | Processing shall encode video as H.264 8-bit MP4 with faststart-friendly packaging and copy audio when possible. | URD-006, URD-013 | Successful outputs are MP4/H.264 (8-bit) suitable for typical Plex/Shield playback. |
| PRD-011 | After a successful process of a `.mov` source, the product shall move the original into a sibling `archive` directory. | URD-007 | Original `.mov` exists under `{sourceDir}/archive/` after success; failure to archive must not mark the job failed if the output was written. |
| PRD-012 | The product shall queue processing jobs and run at most three jobs concurrently. | URD-008 | A fourth job waits until an active job finishes; statuses include queued, processing, completed, and failed. |
| PRD-013 | The product shall expose job progress and status so the operator can monitor work without push channels. | URD-008 | While jobs are queued or processing, the UI refreshes status at least every few seconds via the jobs API. |
| PRD-014 | The product shall reject starting a second process job for a file that already has a queued, processing, or completed job. A failed job may be retried. | URD-004, URD-008 | A process request for an in-flight or completed job id returns a client error; a failed job can be started again. |
| PRD-015 | Scan results required for processing shall be retained for the life of the running service session. | URD-002, URD-004 | After a successful scan, process by returned file id succeeds until the service restarts or a new scan replaces results. |
| PRD-016 | The product shall always show the current directory as an editable path the operator can select, copy, paste, and edit; Enter shall browse that path. Clickable breadcrumb segments shall navigate to ancestors without hiding the full path field. | URD-010 | Pasting a valid path and pressing Enter lists that folder; clicking a breadcrumb ancestor lists that ancestor; the path field still shows the full path. |
| PRD-017 | The browse listing shall be a list with Name, Type, and Size; folders open on click; videos show type and size. | URD-001, URD-010 | Folders and videos appear as rows (not a tile grid); clicking a folder changes the current directory. |
| PRD-018 | The operator shall be able to filter listed videos by type: All, MOV, MP4, M4V. Folders remain visible in browse. | URD-011 | Choosing MOV hides other video types in that listing; folders still appear. |
| PRD-019 | The operator shall be able to sort browse and scan lists by name, type, or size (ascending or descending). Default browse: folders first, then name A–Z. | URD-011 | Clicking Size twice reverses order; folders stay grouped first in browse. |
| PRD-020 | Scan results shall use the same type filter and name/type/size sort; the displayed count shall be the filtered set; bulk select and process shall apply to visible selected rows. | URD-004, URD-011 | Filtering to MOV shows only MOV scan rows; Process Selected only starts jobs for selected rows in that filtered list. |
| PRD-021 | After a scan, the operator shall be able to filter results to needs rotation, would benefit from optimization, either of those (“needs work”), or all files. Suggestion filters combine with type (AND). Identification rules remain PRD-005. | URD-012 | Needs rotation shows only `suggestRotation`; Optimize shows only `suggestOptimization`; Needs work shows either; MOV + Optimize shows large MOVs only. |
| PRD-022 | When optimization is requested, the output file shall be smaller than the source file. | URD-006, URD-013 | For a large MOV processed with optimize, output size is less than the original. Convert-only without optimize or rotation may remux without re-encoding. |
| PRD-023 | Re-encodes shall use H.264 8-bit (no HEVC re-encode). | URD-006 | Processed MP4 video is H.264 8-bit unless the job remuxed without re-encoding. |
| PRD-024 | The operator shall be able to select one or more videos in the folder listing and run Actions on that set (process, restore, restore and drop converted, delete archive). | URD-004, URD-019, URD-020 | Selecting videos and choosing Process from Actions enqueues work for eligible rows. Restore and Delete archive apply only to selected rows that support them, after a confirm. |
| PRD-025 | When Include subfolders is on, the folder listing shall include nested videos and show the relative folder path from the current directory (not only the filename). Files in the current directory itself shall omit that extra path. | URD-015 | A listing of a library that contains `2026/July/clip.MOV` shows `2026/July/` in the Name column. |
| PRD-026 | Opening a directory shall list folders and videos in one list and start analysis of those videos automatically. Status on the row shall offer Optimize & Rotate when orientation still needs baking in, or Optimize when a large MOV still needs shrinking. Restore and archive-delete run from the Actions menu for selected rows. Leaving the directory shall stop the in-progress analysis. | URD-016, URD-003 | After opening a folder, a non-zero rotation file shows Optimize & Rotate in Status (no “Requires Rotation” tag). A `.mov` over 100MB with no rotation shows Optimize. Navigating to another folder stops probing the previous folder. |
| PRD-027 | Scan metadata and thumbnails shall be stored in a `.vidorient/` folder inside each directory that contains the videos (`metadata.json` plus a `thumbs/` tree), including when the operator listed those videos by scanning a parent with subfolders included. Later visits shall reuse that metadata unless the video’s last-modified time (or size) has changed. | URD-016, URD-021 | A second visit to an unchanged folder does not re-probe every file; editing a video’s mtime causes that file to be probed again. Stills appear in the listing once generated. A recursive listing of a parent does not write nested videos’ metadata into the parent `.vidorient/` folder. |
| PRD-028 | The operator shall be able to jump to Home (user home directory), `/Volumes`, and starred favorite folders from the path chrome. | URD-017 | Home opens the user home directory. `/Volumes` stays available. Starring the current folder adds it to Favorites; selecting a favorite lists that folder. |
| PRD-029 | The folder listing shall group an original, converted output, and archived original into one row and show original / converted / archive sizes when those files exist. | URD-018 | A processed MOV that produced an MP4 and moved the MOV to `archive/` appears as one row with those sizes, not three independent videos. |
| PRD-036 | When original and converted sizes are known, the listing shall show how much smaller the converted file is (percent of original size saved) and the bytes saved. Those sizes shall remain in folder metadata after the original or archive is deleted. | URD-023, URD-018 | After process, the Size column shows a savings line (for example −50% · 157 MB). Deleting the archive still shows Orig/Conv sizes and the same savings from stored metadata. |
| PRD-030 | The operator shall be able to restore selected archived originals to their previous paths via Actions. Restore shall refuse to overwrite a file already at that path. If requested, each converted file shall be deleted only after that original is restored and verified. | URD-019 | Restoring when the original path is empty puts the archive back. Asking to drop the converted file leaves the original in place even if converted delete fails after restore. |
| PRD-031 | The product shall delete an archived original only when a converted file is present and checks out as a playable video of expected duration. | URD-020 | Delete archive is refused when the converted file is missing or fails the playback check; the archive file remains. |
| PRD-032 | After encoding, the product shall verify the converted file is a playable video before moving a `.mov` original into `archive/`. If an archive file with that name already exists, the original shall not be moved. | URD-007, URD-020 | A failed verify does not archive the original. A name collision in `archive/` leaves the original in place and still marks the job completed with a warning. |
| PRD-033 | The product shall refuse to start processing when the intended output path already exists. | URD-006, URD-020 | A process request whose output file is already on disk returns a client conflict error and does not overwrite. |
| PRD-037 | The operator shall be able to rename a listed video from a pencil control beside the filename. The editor shall show the current name without the extension, with the extension visible and not editable, and shall select that name so typing replaces it. Confirming shall rename related original, converted, and archived files to that base name (each keeping its own extension), refuse overwrite, and keep the first-seen filename in folder metadata. The listing shall update that row in place without reloading or re-sorting. | URD-024, URD-018 | The field opens with the stem selected and `.mp4` / `.mov` shown beside it. After rename, that row shows the new name in the same position. Rescan or clicking a sort header re-applies order. Converted/archived copies stay one row; the original capture name remains visible when it differs. |
| PRD-038 | On launch, the product shall open the last directory this browser successfully listed, persisted in the same browser storage as starred favorites. If that directory cannot be listed, it shall fall back to `/Volumes`. | URD-025, URD-010 | Closing the app in folder A and reopening lists A. Clearing that stored path (or an unreadable A) lists `/Volumes`. |

## Known product gaps (documented, not required yet)

| Gap | Notes |
| --- | --- |
| Persistence | Processing jobs are not retained across service restarts. Scan metadata and thumbnails persist per folder in `.vidorient/`. |
